Codexの回答は、内容はこれでいいのに日本語だけ少し硬い、ということがあります。

そこで最後にGeminiへ渡して、文章だけ整えてもらおうとしました。簡単に済むと思っていたのですが、最初の評価でさっそく意味が変わりました。

元の文はこれです。

> Bより安いからではなく、保守の手間が小さいためです。

Geminiに普通に書き直させると、こうなりました。

> Bよりも安価だからという理由だけでなく、保守の手間が小さいためです。

元の文では、安さは理由ではありません。書き直した文では、安さも理由の一つになっています。

日本語だけ直してほしいのに、内容まで変わっていました。

## Geminiには考え直させない

今は、Codexで内容を確定してからGeminiへ渡しています。

```text
Codexで調査・判断・実行まで終える
  ↓
数字やURLなどを一時的に隠す
  ↓
Geminiで日本語だけ整える
  ↓
隠した値を元に戻す
  ↓
Markdownの形を機械的に確認
  ↓
Codexで元の意味と変わっていないか確認
```

Geminiには検索履歴やツールの実行履歴を渡しません。渡すのは、Codex側で内容を確定したあとの文章だけです。

日付、URL、コード、金額、ファイルパスなどは、そもそも書き換えさせません。

```text
2026年9月4日
↓
⟦LOCK_0001⟧

`npm run build`
↓
⟦LOCK_0002⟧
```

こんなふうに一時的な記号へ置き換えます。Geminiから返ってきたときに記号が消えていたり増えていたりすれば、その出力は使いません。

## コードだけでは守れない部分もあった

評価を19ケースまで増やすと、別の問題が出ました。

元の文章では、

1. 移行が必要
2. A案を採用
3. A案は作業量が少ない

と3つの事実を並べていただけでした。

ところが書き直し後は、

> A案は作業量が少ないためです。

となりました。

「作業量が少ないからA案を選んだ」という理由を、Geminiが勝手に足しています。

Markdownも数字も壊れていないので、これはコードでは見つけられません。そこで最後にCodexで原文と見比べ、因果関係や確信度まで確認するようにしました。

もう一つ、こんな例もありました。

> この対応を実施するという方向性で進めることが適切であると考えています。

が、

> この対応を進める方向で検討するのが適切です。

に変わりました。

「実施する方向」が「検討」に戻り、「考えています」も断定に変わっています。文章はすっきりしていても、元と同じ内容ではありません。

今の版では、因果関係や確信度に加えて、「検討」「予定」「決定」「実施」のような段階も変えないようにしています。

同じ19ケースで再評価した結果は次のとおりです。

| 項目 | 結果 |
| --- | ---: |
| 機械的な確認 | 19/19 成功 |
| 実行エラー | 0 |
| 実際に文章が変わったケース | 9/19 |
| 手動確認で見つかった重大な意味変化 | 0 |

19件を1回ずつ試した結果なので、これだけで安全性を証明できるわけではありません。

また、安全側に寄せるほど指示文は長くなります。19ケースの入力トークンは `7,340 → 12,755 → 17,980` と増えました。

## この記事も最後に通した

この記事の本文も、公開前に同じ処理へ通しています。

最初の実行では、本文中の

> Aを弱く推奨しているような表現

が、

> Aを強く推奨しているような表現

に変わりました。

最後の確認で見つけたので、その出力は使っていません。「弱く / 強く」「少し / かなり」のような程度も変えないようルールを足して、もう一度実行しました。

2回目は本文が1文字も変わらず、そのまま返ってきました。この原稿はその版です。

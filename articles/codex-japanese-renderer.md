Codexの回答は、そのままでも十分読めます。

ただ、日本語だけもう少し自然にしたい場面があります。そこで最後にGeminiへ「自然な日本語にして」と渡してみると、文章は読みやすくなる一方で、意味まで変わることがありました。

たとえば元の文が、

> Bより安いからではなく、保守の手間が小さいためです。

だったとします。

Geminiに普通に書き直させると、実際の評価ではこうなりました。

> Bよりも安価だからという理由だけでなく、保守の手間が小さいためです。

前者は「安さは理由ではない」。後者は「安さも理由の一つ」です。

そこで、**Codexで内容を確定し、Geminiには日本語だけ整えさせる**仕組みを作りました。

## 役割を分ける

```text
Codexで調査・判断・実行まで終える
  ↓
数字やURLなどを保護
  ↓
Geminiで日本語だけ整える
  ↓
保護した値を元に戻す
  ↓
Markdown構造を機械検証
  ↓
Codexで意味を最終確認
```

Geminiには検索履歴やツール実行履歴を渡しません。渡すのは、Codex側ですでに内容を確定した最終原稿だけです。

## 壊されたくない値は触らせない

日付やURL、コード、金額などはGeminiへ送る前に一時的な記号へ置き換えます。

```text
2026年9月4日
↓
⟦LOCK_0001⟧

`npm run build`
↓
⟦LOCK_0002⟧
```

保護するのは、コード、URL、日付、金額、割合、ファイルパス、バージョン文字列などです。

Geminiの出力後、すべての記号が1回ずつ残っていることを確認して元に戻します。消えたり増えたりしていれば、その出力は使いません。

## 普通の書き直しでは何が起きたか

同じ原稿を、Codexの原文、Geminiによる通常の書き直し、今回の制約付き書き直しの3通りで比較しました。モデルは `gemini-3.5-flash-lite` です。

通常の書き直しでは、次のような変化が出ました。

- `## 実行方法` という見出しが消える
- `¥3,500` が `3,500円` に変わる
- 「意味まで動きやすくなる」が「意味まで変わってしまう」になり、断定が強くなる
- 「Aを推奨するとまでは言えない」が、Aを弱く推奨しているような表現に変わる

どれも自然な日本語ですが、元の意味や構造は保てていません。

## 機械検証だけでも足りなかった

評価を19ケースまで増やすと、制約付きの書き直しでも問題が見つかりました。

元の文章では、

1. 移行が必要
2. A案を採用
3. A案は作業量が少ない

という3つの事実を並べていただけでした。

ところが、書き直し後は、

> A案は作業量が少ないためです。

となりました。

「作業量が少ないからA案を選んだ」という因果関係を勝手に作っています。

Markdownの構造検証は通っていました。**形が壊れていなくても意味は動く**ということです。

そこで、コードでは記号の欠落やMarkdown構造だけを確認し、意味はCodexが原文と比較するようにしました。

確認するのは、事実、結論、確信度、条件、因果関係、「検討」「予定」「決定」「実施」といった段階です。

## 19ケースで調整した結果

日本語を積極的に直すようにした版では、今度は別の問題が出ました。

> この対応を実施するという方向性で進めることが適切であると考えています。

が、

> この対応を進める方向で検討するのが適切です。

に変わりました。

「実施する方向」が「検討」に戻り、「考えています」が断定に変わっています。

そこで最終版では、確信度を表す言葉と、検討・予定・決定・実施といった段階を勝手に変えないよう明示しました。

同じ19ケースで再評価した結果です。

| 項目 | 結果 |
| --- | ---: |
| 機械検証 | 19/19 成功 |
| 実行エラー | 0 |
| 原文から変更された出力 | 9/19 |
| 手動確認で見つかった重大な意味変化 | 0 |
| 平均API応答時間 | 728 ms |

19件を1回ずつ試しただけなので、安全性を証明できたわけではありません。

安全ルールを増やした分、19ケースの入力トークンは `7,340 → 12,755 → 17,980` と増えました。安全性とコストにはトレードオフがあります。

## まとめ

一番大事だったのは、良い指示文を書くことよりも、**何をAIに任せ、何をコードで固定するかを決めること**でした。

数字やURLは触れないようにする。Markdown構造はコードで確認する。意味は別の工程で確認する。

Geminiには調査も判断もさせず、日本語だけ整えさせる。

今のところ、この分け方が一番扱いやすいです。

## この記事について

この記事の本文も、公開前に同じ仕組みに通して意味を確認しています。

最初の実行では「Aを弱く推奨しているような表現」が「Aを強く推奨しているような表現」に変わりました。そこで出力を差し戻し、程度や強さを表す言葉も勝手に変えないようルールを追加しています。

修正後にもう一度この記事を通し、意味が変わっていないことを確認したものがこの最終稿です。
